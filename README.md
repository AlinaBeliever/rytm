# Ритм: завдання і звички (PWA)

«Ритм» — веб-додаток для щоденних завдань і звичок. Його можна встановити на телефон чи ноутбук як звичайний додаток, і він працює без інтернету. Написаний на чистому HTML, CSS і JavaScript, без фреймворків, збирачів і зовнішніх бібліотек. Шрифти системні, іконки й звуки згенеровані, тож жодних CDN.

Дані зберігаються на пристрої (IndexedDB, працює офлайн) і, після входу в акаунт, синхронізуються через Supabase між усіма пристроями. Пуш-сповіщення приходять із сервера навіть на закритий додаток.

**Бекенд (Supabase, проєкт `rytm`)**: таблиці `tasks`, `habits`, `completions`, `user_meta`, `push_subscriptions`, `sent_reminders` з RLS; Edge Function `send-reminders` щохвилини (pg_cron) шле Web Push. Клієнт: `js/config.js` (публічні ключі), `js/sync.js` (вхід, синхронізація, підписка на пуші). Конфлікти вирішує новіший `updatedAt`. Звички й завдання показуються разом на «Сьогодні» та «Тиждень»; при додаванні тип обирається перемикачем «Завдання / Звичка».

## Як запустити локально (3 кроки)

1. Розпакуйте архів і відкрийте термінал у папці `rytm`.
2. Запустіть простий сервер: `python3 -m http.server 8123`
   (якщо Python не встановлено, підійде `npx serve .`).
3. Відкрийте в браузері **http://localhost:8123**

> Просто двічі клікнути на `index.html` не вийде: service worker і модулі JavaScript працюють тільки через сервер (`http://localhost` або `https://`).

## Як задеплоїти на Netlify

**Варіант 1: перетягуванням (найшвидше)**
1. Зайдіть на app.netlify.com → **Add new site → Deploy manually**.
2. Перетягніть **папку `rytm`** (не zip) у вікно браузера.
3. За хвилину з'явиться адреса на кшталт `https://назва.netlify.app`. Відкрийте її, і додаток можна встановлювати.

**Варіант 2: через GitHub (автоматичні оновлення)**
1. Створіть репозиторій на GitHub і завантажте туди вміст папки `rytm` (щоб `index.html` лежав у корені репозиторію).
2. У Netlify: **Add new site → Import an existing project → GitHub** → виберіть репозиторій.
3. Build command залиште порожнім, Publish directory — `.` (усе це вже прописано в `netlify.toml`). Натисніть **Deploy**.
4. Далі кожен `git push` у гілку `main` автоматично оновлює сайт. Для інших гілок Netlify робить preview-посилання.

**Варіант 3: GitHub Pages (безкоштовно, без лімітів Netlify)**
1. Створіть на GitHub **публічний** репозиторій, наприклад `rytm`, і завантажте туди вміст папки `rytm` (`index.html` має лежати в корені репозиторію).
   Найпростіше без терміналу: на сторінці репозиторію **Add file → Upload files**, перетягніть усі файли й папки, потім **Commit changes**.
2. **Settings → Pages → Build and deployment**: Source — **Deploy from a branch**, Branch — **main**, папка **/ (root)** → **Save**.
3. Через 1–2 хвилини сайт буде за адресою `https://ВАШ-ЛОГІН.github.io/rytm/`. Там працює HTTPS, тож встановлення, офлайн і сповіщення працюють так само.
4. Кожен новий commit у `main` оновлює сайт автоматично.

Примітки щодо GitHub Pages:
- Файл `.nojekyll` у корені вимикає зайву обробку Jekyll. Не видаляйте його.
- `netlify.toml` GitHub ігнорує, він нічого не ламає.
- Безкоштовно Pages працює для публічних репозиторіїв. Видно лише код, ваші дані туди не потрапляють, бо зберігаються тільки на пристрої. Для приватного репозиторію потрібен платний GitHub Pro.
- Ліміти GitHub Pages: сайт до 1 ГБ, приблизно 100 ГБ трафіку на місяць. Для цього додатку (менше 0,5 МБ) це з величезним запасом.
- Додаток уже перевірено за такою адресою з підпапкою (`/rytm/`): усі 93 перевірки пройдено.

**Важливо після змін у коді:** у файлі `sw.js` збільште номер у рядку `const VERSION = 'rytm-v1.0.0'` (наприклад, на `v1.0.1`). Тоді встановлені копії додатку побачать оновлення й покажуть кнопку «Оновити».

## Що вміє додаток

- **Завдання:** вкладки «Сьогодні», «Тиждень», «Без дати»; стрічка дат (свайп на телефоні, стрілки на ноутбуці) і кнопка «Сьогодні»; будь-який минулий чи майбутній день.
- **Тиждень:** на ноутбуці 7 колонок, на телефоні 7 блоків, що згортаються; окремий блок «Завдання на тиждень».
- **Поля завдання:** назва, нотатка, дата, час, пріоритет (3 кольори), повторення (щодня / по буднях / щотижня в обрані дні / щомісяця), кілька нагадувань.
- **Галочка:** завдання плавно переїжджає в «Виконано» (закреслене, приглушене, видиме); повторний клік повертає його вгору. Блок «Виконано» згортається, і цей стан запам'ятовується.
- **Порядок:** спершу завдання з часом, потім за пріоритетом; можна перетягнути (на телефоні — після довгого натискання).
- **Прострочено:** вгорі «Сьогодні», з кнопками «На сьогодні» та «Перенести всі на сьогодні».
- **Швидке додавання:** поле вгорі на ноутбуці (розуміє час: «Дзвінок 15:30», а «!» означає високий пріоритет) і кнопка «+» на телефоні.
- **Відкласти:** 10 хв, 30 хв, 1 год, 3 год, сьогодні ввечері, завтра 9:00, наступний понеділок, свій час. Кнопка є в кожному завданні, у формі, у шторці нагадування і в системному сповіщенні («Відкласти на 15 хв»).
- **Звички:** емодзі, колір, частота (щодня / N разів на тиждень / обрані дні), ціль так/ні або кількість («+1» і кільце прогресу), нагадування. Відмітки заднім числом: стрілками на екрані звичок, у календарі місяця і на екрані «Прогрес».
- **Статистика звички:** теплова карта за рік, календар місяця, поточна й найдовша серія, відсоток за тиждень/місяць/рік, стовпчики по тижнях. Екран «Прогрес» показує всі звички за 7 або 30 днів однією сіткою.
- **Нагадування:** системне сповіщення + звук (4 звуки, гучність, «Без звуку»), тихі години, нагадування за замовчуванням, ранкове зведення, список пропущених нагадувань.
- **Дизайн:** світла й темна тема (автоматично + перемикач), нижнє меню на телефоні, бічна панель на ноутбуці, зони натискання від 44 px, плавні анімації (вимикаються, якщо в системі ввімкнено «зменшити рух»).
- **Доступність:** контраст WCAG AA (перевірено axe-core на всіх екранах в обох темах), підписи до всіх іконок, видимий фокус, гарячі клавіші.
- **Гарячі клавіші:** `N` нове завдання (працює й на українській розкладці — `Т`), `Пробіл` відмітити виділене завдання, `←`/`→` попередній/наступний день (у «Тижні» — тиждень), `↑`/`↓` рух між завданнями, `Enter` відкрити, `Alt+↑/↓` перемістити завдання. У полях введення клавіші не спрацьовують.
- **Дані:** експорт і імпорт JSON (з номером версії схеми, перевіркою файлу й вибором «Об'єднати» або «Замінити все»), «Стерти всі дані».

## Прийняті рішення

Тут те, що не було прямо описано в завданні, і те, як я це вирішив.

1. **Назва — «Ритм».** Коротка, українська, про регулярність: і завдання, і звички — це ритм дня.
2. **Колір і стиль:** спокійний зелено-бірюзовий акцент (#2a7262), теплий світлий фон, у темній темі — майже чорний фон і м'ятний акцент. Іконка — коло з галочкою.
3. **Зберігання.** IndexedDB, 4 «таблиці»: `tasks`, `habits`, `completions` (відмітки), `meta` (налаштування і службове). Кожен запис має `id` (UUID), `createdAt`, `updatedAt`. Видалення «м'яке» (`deletedAt`): для синхронізації видалення теж треба передавати на інші пристрої. Зняту відмітку не видаляю, а ставлю їй `count: 0` з тієї ж причини. Інтерфейс з базою напряму не працює, тільки через `storage.js`.
4. **Повторювані завдання** зберігаються як одне завдання з правилом (`repeat`), відмітки — окремо по датах (`completions`). «Відкласти» для одного випадку записує виняток (`exceptions[рідна дата] = {нова дата, час}`), правило не змінюється.
5. **Щомісяця на 29–31 число:** у коротших місяцях — останній день місяця (31 січня → 28/29 лютого → 31 березня).
6. **«Прострочено»** показує тільки разові завдання (і відкладені випадки повторюваних). Пропущені дні щоденних повторюваних завдань туди не потрапляють, інакше за тиждень відпустки набралося б 7 копій «Зарядки».
7. **«Завдання на тиждень»** (без конкретного дня) зберігаються з полем `weekOf` = понеділок тижня. Тиждень завжди починається з понеділка.
8. **Ручний порядок** (перетягування) запам'ятовується окремо для кожного списку (день, тиждень, «Без дати»). Нове завдання стає на місце за правилом (час → пріоритет), а перетягнуті зберігають свій порядок між собою.
9. **Нагадування працюють тільки для завдань із часом.** У формі є підказка, якщо час не вказано.
10. **Відкладене завдання нагадує рівно в новий час, один раз**, незалежно від початкових «за 10 хв» тощо. Інакше «Відкласти на 10 хв» з нагадуванням «за 10 хв» спрацювало б миттєво.
11. **Вчасно чи пропущено:** якщо нагадування спрацювало із запізненням до 5 хв (наприклад, браузер пригальмував фонову вкладку), це ще «вчасно» — буде сповіщення і звук. Якщо додаток був закритий довше, нагадування потрапляє в список «Пропущені» при наступному відкритті (дивлюсь до 7 днів назад).
12. **Тихі години (за замовчуванням 23:00–8:00):** у цей час немає ні сповіщень, ні звуку. Нагадування, які припали на тихі години, з'являються у списку «Пропущені», щойно ви відкриєте додаток.
13. **Ранкове зведення** приходить, якщо додаток відкритий (або згорнутий) у вибрану годину. Після бекенду воно прийде й на закритий додаток через Web Push.
14. **Часовий пояс.** Час завдань зберігається як «місцева дата + місцевий час» (наприклад, `2026-11-20` + `09:00`). Нагадування щоразу рахується від поточного поясу пристрою, тому в подорожі 9:00 лишається 9:00 за новим місцевим часом. При зміні поясу додаток показує повідомлення.
15. **Серії звичок:**
    - «Щодня» — днів поспіль. Сьогоднішній ще не відмічений день серію не обриває (день іще не закінчився).
    - «В обрані дні» — поспіль виконаних **запланованих** днів; незаплановані дні (наприклад, вихідні для звички «пн, ср, пт») серію не обривають і не додають до неї.
    - «N разів на тиждень» — серія рахується в **тижнях**: скільки тижнів поспіль виконано норму (≥ N днів). Поточний тиждень, де норму ще не набрано, серію не обриває.
    - Кількісна звичка («8 склянок») зараховує день, коли досягнуто цілі; неповний день видно як блідішу клітинку.
16. **Відсотки «за тиждень / місяць / рік»** рахуються за останні 7 / 30 / 365 днів, але не раніше дня, коли звичку створили (або першої відмітки заднім числом). Для «N разів на тиждень» очікувана кількість = N × днів / 7.
17. **Нагадування звички** приходить тільки в дні за розкладом і тільки якщо звичку ще не виконано.
18. **Стан дозволу на сповіщення** перевіряю через Permissions API (у деяких браузерах `Notification.permission` показує застаріле значення).
19. **Кешування в service worker:** файли віддаються з кешу миттєво (тому працює без інтернету), а в фоні оновлюються з мережі. Номер `VERSION` у `sw.js` — щоб гарантовано оновити всі копії.
20. **Звуки** синтезуються через Web Audio API (Дзвіночок, Маримба, Два тони, Краплі), без аудіофайлів. Браузери дозволяють звук лише після першого дотику до сторінки, тому звук «розблоковується» при першому кліку.
21. **Приклади при першому запуску:** 7 завдань і 3 звички з невеликою історією, щоб статистика не була порожньою. Позначені міткою «приклад», видаляються кнопкою «Видалити приклади» (на «Сьогодні», у «Звичках» або в налаштуваннях).
22. **Поля часу** показуються у форматі пристрою (на українських налаштуваннях — 24 години).

## Обмеження нагадувань без бекенду (чесно)

- Нагадування спрацьовують, **поки додаток відкритий**: у вкладці (зокрема фоновій) або згорнутий. Якщо браузер чи додаток повністю закрити, нагадувань не буде, а при наступному відкритті з'явиться список «Пропущені нагадування».
- Браузери пригальмовують фонові вкладки: Chrome після ~5 хв у фоні запускає таймери приблизно раз на хвилину. Тому я перевіряю нагадування кожні 20 с і одразу при поверненні на вкладку. Сповіщення може запізнитися максимум на ~1 хв.
- На телефонах система може «заморозити» згорнутий додаток через кілька хвилин, тоді нагадування прийде, коли ви його відкриєте. Надійні нагадування на закритий телефон будуть тільки з Web Push (етап бекенду).
- **iPhone:** сповіщення працюють тільки в додатку, **встановленому на головний екран** (iOS 16.4+), і тільки поки він відкритий. У звичайній вкладці Safari сповіщень немає. Кнопки дій у сповіщенні («Виконано», «Відкласти») iPhone не показує. Натискання відкриває додаток, і там є ці кнопки.
- Кнопки дій у сповіщенні підтримують Chrome/Edge на Windows, Android і ChromeOS. На macOS — залежно від налаштувань системи.

## Що перевірити руками (чекліст на 5–10 хвилин)

Автотести перевірили логіку й інтерфейс у Chromium. Те, що можна побачити й почути тільки на справжньому пристрої:

- [ ] **Ноутбук (Chrome або Edge):** відкрийте сайт → в адресному рядку з'явиться значок «Встановити» → встановіть.
- [ ] **Налаштування → «Увімкнути нагадування»** → браузер питає дозвіл → «Дозволити» → натисніть «Тестове сповіщення»: сповіщення видно і звук чути.
- [ ] **Звуки:** прослухайте 4 мелодії (кнопка ▶), посуньте гучність, увімкніть «Без звуку» й переконайтесь, що тихо.
- [ ] **Справжнє нагадування:** створіть завдання на час через 2 хвилини з нагадуванням «У момент» → згорніть браузер → має прийти сповіщення зі звуком. Натисніть у ньому «Відкласти на 15 хв» (або клацніть на сповіщення й виберіть «Відкласти → 1 год»): час завдання зміниться.
- [ ] **Android (Chrome):** відкрийте адресу → меню ⋮ → «Встановити додаток» → відкрийте з іконки → увімкніть режим польоту → додаток відкривається й показує дані.
- [ ] **iPhone (Safari):** «Поділитися» → «На початковий екран» → відкрийте з іконки → Налаштування → «Увімкнути нагадування» → «Тестове сповіщення».
- [ ] **Телефон:** свайпніть стрічку дат; довго натисніть на завдання й перетягніть його вище/нижче; заголовок дня можна свайпати вліво/вправо.
- [ ] **Тема:** перемкніть телефон у темний режим — додаток теж потемніє (або виберіть тему вручну в налаштуваннях).
- [ ] **Резервна копія:** «Експорт у JSON» → файл завантажився → «Імпорт з JSON» цього ж файлу → «Об'єднати».

## План підключення бекенду (Supabase)

### 1. Вхід
- Supabase Auth: вхід за email (magic link) і, за бажанням, Google/Apple.
- При першому вході: якщо на пристрої вже є дані, вони завантажуються в акаунт (це просто перший «push» синхронізації).

### 2. Таблиці (усі з `user_id uuid references auth.users` і Row Level Security `user_id = auth.uid()`)

| Таблиця | Поля |
|---|---|
| `tasks` | `id uuid pk`, `user_id`, `title text`, `note text`, `date date`, `time time`, `week_of date`, `priority smallint`, `repeat jsonb`, `reminders int[]`, `done bool`, `done_at timestamptz`, `snoozed bool`, `exceptions jsonb`, `sample bool`, `created_at`, `updated_at`, `deleted_at` |
| `habits` | `id uuid pk`, `user_id`, `name`, `emoji`, `color`, `freq jsonb`, `goal jsonb`, `reminder_time time`, `start_date date`, `end_date date`, `day_marks jsonb`, `archived bool`, `order int`, `sample bool`, `created_at`, `updated_at`, `deleted_at` |
| `completions` | `id uuid pk`, `user_id`, `kind text ('task'/'habit')`, `ref_id uuid`, `date date`, `count int`, `created_at`, `updated_at`; **unique (user_id, kind, ref_id, date)** |
| `settings` | `user_id pk`, `value jsonb` (ті самі поля, що зараз), `timezone text`, `updated_at` |
| `push_subscriptions` | `id`, `user_id`, `endpoint text unique`, `p256dh text`, `auth text`, `user_agent`, `created_at` |
| `sent_reminders` | `id text pk` (той самий ідентифікатор, що в додатку: `завдання|дата|час|зсув`), `user_id`, `sent_at` — щоб не надіслати двічі |

Тригер на кожну таблицю: `updated_at = now()` при оновленні.

### 3. Синхронізація і конфлікти
- Додаток і далі працює з локальною IndexedDB (офлайн), а Supabase стає «хмарною копією».
- Кожна зміна потрапляє в локальну чергу `outbox`. Коли є інтернет (подія `online`, повернення на вкладку, раз на кілька хвилин), черга відправляється `upsert`-ом.
- Отримання змін: `select * where updated_at > lastSyncAt` для кожної таблиці + Realtime-підписка для миттєвих оновлень.
- **Конфлікти:** «перемагає новіша версія запису» (last-write-wins за `updated_at`) — так само вже працює імпорт з об'єднанням. Видалення передаються через `deleted_at`. Для `completions` ключ — `(kind, ref_id, date)`, тож дві відмітки одного дня з двох пристроїв зливаються в одну.
- Щоб годинники різних пристроїв не заважали, `updated_at` на сервері ставить тригер, а локальне значення використовується тільки до першої синхронізації.

### 4. Пуш-нагадування за розкладом (Web Push)
1. Згенерувати VAPID-ключі (`npx web-push generate-vapid-keys`). Приватний ключ — у секрети Supabase, публічний — у додаток.
2. Після «Увімкнути нагадування» викликати `subscribeToPush(VAPID_PUBLIC_KEY)` з `notifications.js` і зберегти результат у `push_subscriptions`.
3. **Edge Function `send-reminders`** (Deno + `npm:web-push`): бере завдання й звички користувачів, рахує нагадування за останню хвилину **в часовому поясі користувача** (`settings.timezone`) тією самою логікою, що й `reminderEvents()` у `logic.js` (файл можна імпортувати у функцію майже без змін), враховує тихі години, перевіряє `sent_reminders` і надсилає push у форматі, який уже розуміє `sw.js`:
   `{ "title": "...", "body": "...", "tag": "<той самий id>", "data": { "kind": "task", "taskId": "...", "occDate": "YYYY-MM-DD" } }`
4. **Cron:** `pg_cron` + `pg_net` викликають функцію щохвилини (`select cron.schedule('reminders', '* * * * *', ...)`). Ранкове зведення — та сама функція.
5. Обробники `push` і `notificationclick` у `sw.js` уже готові: кнопки «Виконано» і «Відкласти на 15 хв» відкриють/розбудять додаток і виконають дію. Пізніше можна дати service worker'у самому записувати дію в Supabase, щоб не відкривати додаток.

### Що змінити в `storage.js`
- Додати клієнт Supabase і функції `signIn`, `signOut`, `getUser`, `sync()`.
- `saveTask / saveHabit / setCompletion / saveSettings / delete*` — після запису в IndexedDB додавати запис у чергу `outbox` і запускати `sync()`.
- `get*` лишаються як є (читають локальну копію) — інтерфейс змінювати не треба.
- `subscribe()` уже сповіщає інтерфейс про зміни; викликати `emit()` також після отримання змін із сервера.

### Що змінити в `notifications.js`
- Після отримання дозволу — `subscribeToPush()` і збереження підписки в Supabase.
- Локальний планувальник можна лишити як запасний: сповіщення з однаковим `tag` браузер не дублює, бо додаток і сервер використовують один і той самий ідентифікатор нагадування.
- Записувати часовий пояс пристрою в `settings.timezone` (уже визначається через `Intl.DateTimeFormat().resolvedOptions().timeZone`).
